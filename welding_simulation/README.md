# 3D Thermo-Mechanical Welding Simulation with FEniCSx

A three-dimensional finite element simulation of the transient thermal and elastoplastic mechanical behavior of a welding process, implemented using **FEniCSx**, **Gmsh**, and **PETSc**.

The project is designed to run in **Google Colab** and provides a workflow for generating the mesh, solving the coupled thermal and mechanical problems, and exporting simulation results for post-processing and visualization.

## Overview

This project implements a 3D thermo-mechanical welding simulation using the finite element method (FEM). It models the transient temperature distribution generated by a moving welding heat source and the resulting elastoplastic mechanical response of the steel plate.

The workflow includes:

1. Generating the plate geometry and finite element mesh.
2. Computing the transient thermal field using a moving heat source.
3. Accounting for convection and radiation at exposed surfaces.
4. Computing the mechanical response using temperature-dependent material properties and J2 von Mises elastoplasticity.
5. Exporting simulation data for post-processing, visualization, and downstream data analysis.

The primary execution environment is Google Colab, with project files stored in Google Drive.

## Physical Model

### Geometry and Mesh

- **Workpiece:** Steel plate.
- **Dimensions:** 120 × 100 × 3 mm.
- **Mesh:** Structured hexahedral mesh.
- **Element type:** HEX8 (eight-node hexahedral elements).

### Moving Heat Source

The welding heat input is modeled using the **Goldak double-ellipsoid heat source**.

| Parameter | Value |
|---|---:|
| Welding power | 1800 W |
| Heat-source efficiency | 0.75 |
| Effective heat input | 1350 W |
| Welding speed | 0.005 m/s |

The heat source moves along the prescribed welding path, producing a transient temperature field in the workpiece.

### Thermal Analysis

The thermal model accounts for heat conduction within the plate and heat losses from exposed surfaces through convection and thermal radiation.

### Mechanical Analysis

The mechanical model uses transient J2 von Mises elastoplasticity with linear isotropic hardening to estimate the material response to the evolving temperature field.

## Material Properties

The steel density is defined as:

rho = 7850 kg/m^3

The following material properties are modeled as temperature-dependent:

- Thermal conductivity.
- Specific heat capacity.
- Young's modulus.
- Yield strength.

These temperature-dependent properties allow the simulation to represent changes in thermal and mechanical behavior during the welding cycle.

## Boundary Conditions

### Thermal Boundary Conditions

Heat loss at exposed surfaces is modeled using convection and radiation.

| Parameter | Value |
|---|---:|
| Ambient temperature | 25 °C |
| Convective heat-transfer coefficient | 15.0 W/(m²·K) |
| Surface emissivity | 0.70 |

The radiative heat flux depends on the surface temperature and the ambient temperature.

### Mechanical Boundary Conditions

The plate is fully clamped along the edge at \(x = 0\). All three displacement components are constrained:

[u_x = u_y = u_z = 0]

These constraints prevent rigid-body motion and define the mechanical support condition.

### Manual Setup

The following steps describe how to run the workflow in a new Google Colab notebook.

#### 1. Mount Google Drive

```python
from google.colab import drive

drive.mount("/content/drive")
```

#### 2. Download the Project from GitHub

The following code downloads the repository archive and extracts only the `welding_simulation` directory into Google Drive.

```python
import io
import os
import zipfile

import requests

destination = "/content/drive/MyDrive/welding_simulation"

url = (
    "https://github.com/Afshinrommel/"
    "welding-telemetry-streaming/archive/refs/heads/main.zip"
)

os.makedirs(destination, exist_ok=True)

response = requests.get(url, timeout=120)
response.raise_for_status()

prefix = "welding-telemetry-streaming-main/welding_simulation/"

with zipfile.ZipFile(io.BytesIO(response.content)) as archive:
    for item in archive.infolist():
        if item.is_dir() or not item.filename.startswith(prefix):
            continue

        relative_path = item.filename[len(prefix):]
        target = os.path.join(destination, relative_path)

        os.makedirs(os.path.dirname(target), exist_ok=True)

        with archive.open(item) as src, open(target, "wb") as dst:
            dst.write(src.read())

print(f"Project files extracted to: {destination}")
```

> This step assumes that the repository's default branch is `main` and that the project files are located in `welding_simulation/`.

#### 10. Compress and Download the Results

```python
import os
import zipfile

from google.colab import files

results_dir = "/content/drive/MyDrive/welding_simulation/results"
archive_path = "/content/results.zip"

if not os.path.isdir(results_dir):
    raise FileNotFoundError(
        f"Results directory not found: {results_dir}"
    )

with zipfile.ZipFile(
    archive_path, "w", compression=zipfile.ZIP_DEFLATED
) as archive:
    for root, _, filenames in os.walk(results_dir):
        for filename in filenames:
            path = os.path.join(root, filename)
            archive_name = os.path.relpath(path, results_dir)
            archive.write(path, archive_name)

files.download(archive_path)
```

The archive contains the files available in the `results` directory at the time of compression.

## Results and Output Files

Simulation outputs are stored in the `results/` directory.

Expected output categories include the following.

### Thermal Results

- `thermal.xdmf` — XDMF metadata for thermal results.
- Associated HDF5 data files.
- `thermal_series.jsonl` — thermal time-series data.

### Mechanical Results

- `mechanical_elastoplastic.xdmf` — XDMF metadata for mechanical results.
- Associated HDF5 data files.

### Mesh and Topology Data

- `mesh_topology.json` — mesh connectivity or topology information.
- `volumetric_elements.jsonl` — volumetric element data.

The exact filenames and contents depend on the scripts and configuration used for a particular simulation run.

XDMF/HDF5 files can be used for scientific visualization and post-processing. JSON Lines files are suitable for structured data processing and integration with analysis tools or dashboards.

## Simulation Configuration

The simulation duration and time-step size are controlled by `config.py`.

The current demonstration configuration uses:

| Parameter | Value |
|---|---:|
| Simulation duration | 4 s |
| Time-step size | 0.02 s |
| Number of time increments | 200 |


The time-step size and simulation duration affect computational cost, temporal resolution, and output-file size.

To change the simulation duration, update the corresponding configuration parameter in `config.py` and ensure that the selected time step and solver settings are appropriate for the intended analysis.

## Next Steps: Data Pipeline Integration

Once the simulation is complete and the results are downloaded, the output files (specifically `.jsonl` and `.json` files) are ready to be ingested by the Kafka streaming pipeline.

To integrate these results with the real-time telemetry dashboard:
1. Navigate to the root directory of the main streaming repository: [welding-telemetry-streaming](https://github.com/Afshinrommel/welding-telemetry-streaming/tree/main).
2. Ensure a directory named `result_data_welding/` exists at the root level.
3. Move all generated `.jsonl` and `.json` files from your Colab `results/` folder into this `result_data_welding/` directory.

The Dockerized Kafka producer is pre-configured to automatically mount and stream data directly from this folder.
